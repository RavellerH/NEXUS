Cross-Audit Findings (GEMINI-AUDIT.md)

Gemini 3.5 Flash independently audited the same documentation. Two unique findings were confirmed and applied.

Applied

GA01 — Air-Gap Paradox

NEXUS markets "No cloud. No data leaks." but the default setup pulls ~5.6 GB from the internet on first run. Industrial EPC sites frequently operate behind strict firewalls with no outbound internet access.

Applied to: docs/business/infrastructure.md — added Air-gap paradox section with two deployment paths (online default + offline override), docker-compose.offline.yml spec, and scripts/package-models.sh. Also added offline bootstrap tasks to Phase 1 todo.
Applied

GA02 — Hybrid SQLite FTS5 Index for Alphanumeric Precision

Dense embeddings cannot reliably distinguish AT-201 from AT-202, or CBL-001-HV-4 from CBL-001-HV-3. Semantic search on instrument tags, part numbers, and PO numbers produces wrong results with high confidence scores.

Applied to: docs/modules/context-store/vector-store.md — full Hybrid Index section with SQLite FTS5 schema, query routing logic (EXACT_PATTERN regex), fts_search() and hybrid_query() interface. docs/modules/query/query-engine.md — updated to use hybrid_query() as primary entry point.

Critical Issues — Fix Before Writing Code

Fixed C01

Wrong Embedding Model Name Breaks First-Run Setup

File: docs/business/infrastructure.md
milkey-mouse/multilingual-e5-large is not a valid Ollama namespace. Would cause docker-compose up to fail on first run.

Fixed: Changed to intfloat/multilingual-e5-large (correct Ollama registry name).
Open C02

3 Module Specs Missing — Blocks Phase 1 Implementation

The following modules appear in data flow diagrams and todo.md but have no spec file:

  • docs/modules/ingestion/metadata-tagger.md
  • docs/modules/ingestion/chunker.md (or clarify it's per-parser only)
  • docs/modules/ingestion/ingestion-pipeline.md
Fix: Create ingestion-pipeline.md (orchestration, error handling, retry). Create metadata-tagger.md. Clarify chunker scope per D11.
Open C03

API Error Responses Not Specified — Will Cause Rework

File: docs/modules/api/api.md
API spec defines success responses but no error responses. Frontend developer has no contract for failure states. What code does POST /projects/{id}/query return if project doesn't exist?

Fix: Add error contract to api.md with standard JSON shape: {"error": "string", "code": "PROJECT_NOT_FOUND | UNAUTHORIZED | ...", "detail": "string"}
Open C04

JWT Token Lifecycle Unspecified — Security Gap

File: docs/modules/api/api.md
POST /auth/refresh listed but not specified. Access token TTL unspecified (could be infinite). No logout / revocation mechanism. No JWT_SECRET rotation procedure.

Fix: Access token TTL: 8h. Phase 1: re-login on expiry. Logout: DELETE /auth/session adds token to in-memory blocklist. Role change effective on next login. JWT_SECRET rotation: change in .env + restart.
Open C05

No Ingestion Error Handling Strategy

Files: docs/todo.md, all ingestion module specs
No system-wide answer: if 4 files are uploaded and file 3 fails, do files 1, 2, 4 commit? If ingestion crashes mid-PDF, does it resume or restart? How does the PM know a file failed?

Fix: Per-file isolation. Failure of one file doesn't block others. Partial success with per-file status and error reason. Re-ingestion is idempotent. Failed files shown in UI with specific error.
